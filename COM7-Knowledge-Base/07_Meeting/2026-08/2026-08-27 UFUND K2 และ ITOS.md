# 2026-08-27 UFUND — K2 และ ITOS

**เรื่อง:** ข้อมูล UFUND สำหรับโครงการ Centralize Data
**เป้าหมายของโครงการ:** รวบรวมข้อมูลลูกค้าจากทุก BU เพื่อทำ Hyper Personalization
**ระบบที่เกี่ยวข้อง:** K2 · ITOS

> ชื่อไฟล์ต้นฉบับระบุ `17_08_2026` แต่หัวเอกสารระบุ 27/08/2026 — ใช้ตามหัวเอกสาร **ต้องยืนยันวันที่จริงอีกครั้ง**

---

## 1. ภาพรวมข้อมูลลูกค้า

| | |
|---|---|
| ลูกค้า Active | **200,000–300,000 ราย** (แยก K2 กับ ITOS) |
| Reject Rate | **30–40%** |
| ประมาณการลูกค้าทั้งหมด | **~500,000 ราย** |
| โครงสร้างข้อมูล | **ลูกค้า 1 คน ต่อ 1 สัญญา** |

K2 เก็บข้อมูลลูกค้าที่ถูก **Reject** ไว้ด้วย — ข้อมูลกลุ่มนี้ **อาจไม่ครบถ้วน 100%**

> ตัวเลขนี้ต่างจากที่ probe ฐาน K2 ได้ (288,205 สัญญา · 343,249 เลขบัตรไม่ซ้ำ)
> เพราะที่ประชุมพูดถึงลูกค้า **Active** ส่วน probe นับทั้งหมดตั้งแต่ปี 2020 → [[K2 Overview]]

---

## 2. การเปลี่ยนระบบ K2 → ITOS

- ช่วงแรก UFUND ใช้ **K2** เป็นระบบหลัก
- เมื่อบริษัทใหญ่ขึ้น เปลี่ยนมาใช้โปรแกรม **iLoan บนระบบ ITOS** ซึ่งเป็นระบบหลักของบริษัท
- **ปัจจุบัน migration ยังไม่เสร็จ**
- แผน: migrate จาก K2 → ITOS **ครบ 100% ภายในสิ้นปี 2026**
- K2 อาจต้องใช้**คู่ขนาน**ไปจนถึงประมาณ **Q1/2027**
- **ข้อยกเว้น:** ข้อมูล UFUND Student อาจต้องอยู่บน K2 ต่อไป

---

## 3. UFUND Student

- แยกข้อมูลออกมาเป็นส่วนเฉพาะ
- มีแนวโน้มว่า **K2 ยังต้องใช้ต่อสำหรับ Student** แม้ migration หลักเสร็จแล้ว

**เหตุผล:**

| เหตุผล | รายละเอียด |
|---|---|
| ไม่มี Credit History / Risk Assessment | นักเรียน/นักศึกษาอาจยังไม่มีรายได้ประจำ |
| รองรับการ IPO ในอนาคต | ต้องเก็บข้อมูลและประวัติย้อนหลังให้ครบ เพื่อรองรับการตรวจสอบและข้อกำกับจากหน่วยงาน เช่น **ธนาคารแห่งประเทศไทย** |

---

## 4. ข้อมูล NCB

| | |
|---|---|
| K2 | **ไม่มีข้อมูล NCB แล้ว** — หยุดเก็บตั้งแต่ **08/2025** |
| ITOS | **มีข้อมูล NCB** |

**ข้อสรุป: ห้ามนำรายละเอียด NCB ของลูกค้ามาเก็บใน Data Lake (S3) โดยตรง** เพราะเป็นข้อมูล Sensitive

แนวทางที่พิจารณา — ดึงเฉพาะ **สรุป / Indicator** ที่จำเป็นต่อการวิเคราะห์:

- ระดับภาระหนี้ **สูง / กลาง / ต่ำ**
- สร้างเป็น Column หรือ Flag ประกอบการวิเคราะห์ Customer
- **ไม่เก็บรายละเอียด NCB ทั้งชุด**

---

## 5. ข้อมูลการชำระเงินและ Collection

จุดเด่นของ UFUND ที่ **BU อื่นไม่มีในลักษณะเดียวกัน**:

- ลูกค้าชำระเงินตรงเวลาหรือไม่
- ลูกค้าชำระครบหรือไม่
- ประวัติการชำระเงิน
- พฤติกรรมและสถานะด้าน Collection

ใช้สร้าง **Customer Payment / Collection Profile** ประกอบการวิเคราะห์ Customer 360 และประเมินพฤติกรรมลูกค้า
→ [[UFUND in Customer 360]] · [[K2 - Payment & Invoice]] · [[K2 - Collection & OD]]

## แนวทางที่ตกลงเบื้องต้น

| # | แนวทาง |
|--:|---|
| 1 | ใช้ **ITOS เป็น Primary Source** ในอนาคต |
| 2 | ใช้ **K2 เป็น Historical / Legacy Source** ระหว่าง migration (คู่ขนานถึงราว Q1/2027) |
| 3 | เก็บข้อมูล K2 ต่อสำหรับ UFUND Student — **สุดท้ายก็ต้อง ingest K2 เข้า S3 ด้วย** |
| 4 | ตรวจ **Data Quality ของ K2** โดยเฉพาะกลุ่ม Reject ว่ามีฟิลด์ที่ต้องการครบแค่ไหน |
| 5 | นำข้อมูล **Payment และ Collection** เข้า S3 |
| 6 | **NCB เก็บเฉพาะ Summary / Indicator** ไม่เอารายละเอียดทั้งชุด |
| 7 | เตรียมแนวทางรองรับการตรวจสอบข้อมูลย้อนหลัง หากมี IPO |
